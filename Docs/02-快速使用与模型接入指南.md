# uLipSync 快速使用与新模型接入指南

本指南面向“已有一个 Unity 角色模型，想让它跟随音频张嘴”的使用者。完成最小配置后，运行时会从 `AudioSource` 取音频、计算嘴型，并把结果写到模型的 BlendShape、Animator 参数或 VRM Expression。

## 先理解三个对象

| 对象 | 做什么 | 是否必需 |
| --- | --- | --- |
| `AudioSource` | 播放 AudioClip 或麦克风声音 | 是 |
| `uLipSync` | 监听播放中的音频，输出音素与音量 | 是（实时分析方案） |
| 表情驱动器 | 将音素映射到模型表情 | 是；三选一或自定义 |

表情驱动器有三种常用类型：

- `uLipSyncBlendShape`：普通 Unity 模型，控制 `SkinnedMeshRenderer` 的 BlendShape；最常用。
- `uLipSyncAnimator`：模型通过 Animator Controller 的 float 参数控制口型。
- `uLipSyncExpressionVRM`：VRM 1.0 模型，控制 VRM Expression。

最常见的连接关系是：

```text
GameObject（AudioSource + uLipSync）
  uLipSync.onLipSyncUpdate
    -> 模型上的 uLipSyncBlendShape.OnLipSyncUpdate
    -> SkinnedMeshRenderer BlendShape
```

## 使用前检查

1. 用项目的 Unity `2021.3.45f2` 打开，或先确认目标 Unity 版本与项目依赖兼容。
2. 确保 Package Manager 能安装/解析 `com.unity.burst` 和 `com.unity.mathematics`；本项目在 `Assets/package.json` 中声明了它们。
3. 导入的角色需要有可用的口型表现通道：BlendShape、VRM Expression 或 Animator 参数至少一种。
4. 准备一段可播放的 AudioClip。第一次调试推荐清晰、单人、无背景音乐的语音。
5. 在 Project Settings > Audio 中确认项目有正常的输出采样率；uLipSync 默认会将分析音频降采样到 16 kHz。

## 最快验证：先运行样例

按下面顺序确认插件本身是否正常：

1. 在 `Assets/Scenes/SampleScene.unity` 或包内 `Assets/Samples/01. Play AudioClip/01-1. Play Audio Clip.unity` 打开样例场景。
2. 点击 Play，确认角色播放音频时有口型变化。
3. 查看样例 GameObject 上的 `AudioSource`、`uLipSync` 和 `uLipSyncBlendShape` 组件，理解其引用关系。
4. 若样例正常而新模型不动，通常是新模型的 BlendShape 映射或事件绑定问题，而不是音频分析问题。

项目还包含麦克风、VRM、烘焙、Timeline、Animator、运行时加载和 WebGL 样例；对应目录位于 `Assets/Samples`。

## 接入普通带 BlendShape 的模型

### 第一步：导入并检查模型

将 FBX、GLB 或预制体放入项目，拖入场景。展开模型层级，找到面部的 `SkinnedMeshRenderer`；在 Inspector 的 Mesh 区域查看 BlendShapes 列表。

记下实际名称。常见命名包括：`A/I/U/E/O`、`vrc.v_aa`、`mouth_A`、`JawOpen` 等。uLipSync 不要求固定名称，但你之后填写的映射必须精确匹配。

如果模型没有任何面部 BlendShape：

- 不能仅靠 uLipSync 自动生成真实口型；需要在 DCC 工具（Blender、Maya 等）制作口型 BlendShape 后重新导入，或改用 Animator/骨骼口型方案。
- 可以临时把音量映射到下巴骨骼，但这是自定义驱动脚本的工作，不是 `uLipSyncBlendShape` 的默认能力。

### 第二步：添加音频与分析器

可将下列组件放在角色根节点，也可把音频播放器放在单独 GameObject：

1. 选择播放音频的 GameObject，添加 `AudioSource`。
2. 将语音 AudioClip 拖到 `AudioSource > Audio Resource/Clip`，按需求勾选 `Play On Awake`。
3. 在同一 GameObject 添加 `uLipSync`。
4. 在 `uLipSync > Profile` 指定一个 Profile。可先使用 `Assets/Assets/Profiles` 下的示例 Profile，后续再为项目声音做校准。

若 `AudioSource` 在另一个 GameObject：在该 AudioSource 对象上添加 `uLipSyncAudioSource`，再把它拖到 `uLipSync > Audio Source Proxy`。这是跨对象获取音频数据的正式方式。

### 第三步：配置 BlendShape 映射

1. 选择角色面部所在的 GameObject，添加 `uLipSyncBlendShape`。
2. 在 `Skinned Mesh Renderer` 字段拖入面部的 `SkinnedMeshRenderer`。
3. 在 `Blend Shapes` 列表添加条目；每个条目填写一个 `phoneme`（例如 `A`）和对应的 BlendShape 索引。
4. 最稳妥的做法是使用组件自定义 Inspector 中的添加功能从 Mesh 的真实 BlendShape 名称选择，避免手填索引错位。
5. 按模型能力完成 `A`、`I`、`U`、`E`、`O` 五项。没有某项时可以复用最相近的嘴形，不要设置为错误的表情。

建议的基础映射：

| uLipSync 音素 | 常见 BlendShape 名称示例 | 视觉目标 |
| --- | --- | --- |
| `A` | `A`、`aa`、`vrc.v_aa` | 张口 |
| `I` | `I`、`ih`、`vrc.v_ih` | 横向/窄口 |
| `U` | `U`、`ou`、`vrc.v_ou` | 收圆嘴唇 |
| `E` | `E`、`ee`、`vrc.v_e` | 半开前口型 |
| `O` | `O`、`oh`、`vrc.v_oh` | 圆口 |

设置建议：

- `Max Blend Shape Value`：Unity BlendShape 通常是 0~100；先保留默认 `100`。
- 每条 `Max Weight`：从 `1` 开始，某个嘴形过强再单独降低。
- `Smoothness`：从 `0.05` 开始；太小会抖，太大会明显拖拍。
- `Use Phoneme Blend`：关闭时只选概率最高的一个嘴形，口型更清晰；开启时按所有音素概率混合，过渡更柔和。建议先开启并观察。
- `Update Method`：通常使用默认 `LateUpdate`，避免被普通动画的同帧更新覆盖。

### 第四步：绑定事件

1. 选择有 `uLipSync` 的 GameObject。
2. 在 `On Lip Sync Update` 事件列表点击 `+`。
3. 把包含 `uLipSyncBlendShape` 的 GameObject 拖到事件对象槽。
4. 在函数下拉框选择 `uLipSyncBlendShape > OnLipSyncUpdate(LipSyncInfo)`。
5. 运行场景并播放音频。

若角色根节点同时有两个组件，也必须明确绑定事件；仅仅“都挂在同一个 GameObject”不会自动连接。

## 接入 VRM 模型

### VRM 1.0

1. 完成 VRM for Unity/UniVRM 的导入和模型实例化。
2. 在 VRM 根节点添加 `uLipSyncExpressionVRM`（该脚本受 `USE_VRM10` 编译符号与 UniVRM 10 API 条件控制）。
3. 配置每个音素到 VRM Expression Clip 的名称，例如 `aa`、`ih`、`ou`、`ee`、`oh`，以模型中实际存在的 Expression 名称为准。
4. 将 `uLipSync.onLipSyncUpdate` 绑定到该组件的 `OnLipSyncUpdate`。

### VRM 0.x

项目有对应样例与 `uLipSyncBlendShapeVRM` 适配器，路径为 `Assets/Samples/04. VRM`。先打开 `04-1. VRM 0.X.unity` 观察所用 UniVRM 版本与 BlendShapeProxy 配置，再复制组件结构到自己的模型。

VRM 的口型并不保证所有模型都以同一名称提供。先检查模型实际 Expression/BlendShape Clip，再做映射。

## 接入 Animator 参数模型

当模型的口型不在 Mesh BlendShape，而在 Animator Controller 中时：

1. 在角色上添加 `uLipSyncAnimator`，指定 `Animator`。
2. 在 Animator Controller 中创建 float 参数，例如 `LipA`、`LipI`、`LipU`、`LipE`、`LipO`。
3. 在动画状态机、Blend Tree 或自定义 StateMachineBehaviour 中使用这些 float 参数驱动嘴形动画。
4. 在 `uLipSyncAnimator > Parameters` 中为每个音素添加一项：填写 `phoneme`、Animator 参数 `name` 与 `maxWeight`。
5. 将 `uLipSync.onLipSyncUpdate` 绑定到 `uLipSyncAnimator.OnLipSyncUpdate`。

`uLipSyncAnimator` 每帧会读取音素概率，将其平滑后叠加到 Animator float 参数。若你的动画系统每帧重置这些参数，应调整执行顺序或使用 `LateUpdate`/`External` 模式。

## 模型在运行时动态加载

对于 Addressables、AssetBundle、网络下载或运行时生成的角色，不能在 Inspector 中提前拖引用。可参考：

`Assets/Samples/10. Runtime Setup/Runtime/uLipSyncBlendShapeRuntimeSetupExample.cs`

其核心逻辑是：找到目标面部的 `SkinnedMeshRenderer`，动态添加 `uLipSyncBlendShape` 和 `uLipSync`，然后按配置表调用 `AddBlendShape(phoneme, blendShapeName)`，最后订阅事件。

简化示例：

```csharp
var lipSync = target.AddComponent<uLipSync.uLipSync>();
lipSync.profile = profile;

var driver = target.AddComponent<uLipSync.uLipSyncBlendShape>();
driver.skinnedMeshRenderer = faceRenderer;
driver.AddBlendShape("A", "vrc.v_aa");
driver.AddBlendShape("I", "vrc.v_ih");
driver.AddBlendShape("U", "vrc.v_ou");
driver.AddBlendShape("E", "vrc.v_e");
driver.AddBlendShape("O", "vrc.v_oh");

lipSync.onLipSyncUpdate.AddListener(driver.OnLipSyncUpdate);
```

在生产代码中，请将“面部节点名”和“音素到 BlendShape 名称”的配置移到 ScriptableObject、JSON 或角色元数据中，不要把每个角色的名称写死在脚本内。

## 麦克风实时输入

1. 打开 `Assets/Samples/02. Mic Input/02-1. Mic Input.unity` 作为参考。
2. 给目标对象添加 `uLipSyncMicrophone`（并按组件 Inspector 选择设备、启动方式）。
3. 保持 `uLipSync` 与表现驱动器的事件绑定和播放 AudioClip 时相同。
4. 真机平台要配置麦克风权限：Android/iOS/WebGL 均需要各自的权限说明与用户授权流程。
5. 用耳机测试，避免扬声器声音被麦克风再次采集，导致回声和口型误触发。

## 离线烘焙：适合剧情、视频和性能敏感场景

实时分析会持续消耗 CPU。固定台词推荐在编辑器中烘焙：先计算每个时间点的唇形数据，再用 `uLipSyncBakedDataPlayer` 随音频回放。

1. 打开 `Assets/Samples/05. Bake/05. Bake.unity`。
2. 在 Editor 菜单或组件 Inspector 中使用 Baked Data 相关工具，选定 AudioClip 与 Profile 后生成 `BakedData` 资产。
3. 在播放对象上添加 `uLipSyncBakedDataPlayer`，指定 `Baked Data` 与可选 `AudioSource`。
4. 将 `uLipSyncBakedDataPlayer.onLipSyncUpdate` 绑定给同一个 BlendShape / Animator / VRM 驱动器。
5. 使用 `Time Offset` 微调音频和视觉对齐，默认 `0.1` 秒是一个起点，不是固定正确值。

注意：`uLipSyncBakedDataPlayer` 只播放已经计算好的数据，不会实时分析新音频。它适合不可变 AudioClip，不适合玩家麦克风。

## Profile 校准：让当前算法适配你的声音

Profile 保存每个音素的 MFCC 原型。示例 Profile 可以先跑通，但若实际声音、语言或录音环境差异大，应校准。

1. 选择现有 Profile，或通过 Create 菜单创建 `uLipSync/Profile`。
2. 确认包含需要的音素名（通常 `A/I/U/E/O`），并将该 Profile 分配给 `uLipSync`。
3. 打开校准样例 `Assets/Samples/01. Play AudioClip/01-2. Calibration.unity` 或 `Assets/Samples/02. Mic Input/02-2. Mic Calibration.unity`。
4. 按页面提示逐个持续发音；每类采集多个稳定片段，避免开头、结尾和噪声。
5. 保存 Profile 并回到目标角色试听。

Profile 的核心参数默认是：16 kHz、1024 样本、30 个 Mel filter bank、12 维 MFCC、L2 距离。首次使用不要同时大量修改参数；先完成可靠的校准，再逐项实验。

## 常见问题排查

| 现象 | 优先检查 |
| --- | --- |
| 完全不动 | `AudioSource` 是否真的在播放；`uLipSync.profile` 是否为空；事件是否绑定到正确驱动器 |
| 有音频但 `uLipSync` 无输出 | `uLipSync` 是否与 AudioSource 同对象，或是否正确设置 `Audio Source Proxy` |
| 只有一个口型 | Profile 中音素数据/名称是否完整；BlendShape 映射是否把多个音素指到同一索引 |
| 嘴一直张开 | 音频含背景噪声；音量阈值范围不合适；其他动画持续写入同一 BlendShape |
| 嘴形太小/太大 | 调整 `maxBlendShapeValue` 或单项 `maxWeight`，不要先改模型资产 |
| 抖动 | 提高 `Smoothness`；检查 AudioClip 是否有噪声；尝试 `Use Phoneme Blend` |
| 明显慢半拍/快半拍 | 检查音频输出延迟、帧率和动画执行顺序；烘焙播放调 `Time Offset` |
| 运行时加载失败 | 检查面部节点名、`SkinnedMeshRenderer` 是否找到、BlendShape 名称大小写是否一致 |
| Animator 覆盖口型 | 把驱动器设为 `LateUpdate`，或让动画状态机不重置口型参数 |
| VRM 没反应 | 检查 UniVRM 版本、编译符号、Expression 名称及使用的是 VRM 0.x 还是 1.0 适配器 |

## 推荐接入顺序

1. 先在样例场景确认插件与 Unity 环境正常。
2. 用一个带清晰 `A/I/U/E/O` BlendShape 的模型接入实时 AudioClip。
3. 调好 BlendShape 映射、权重和 `Smoothness`。
4. 再接入麦克风、VRM、Animator 或运行时动态模型。
5. 固定台词改用烘焙数据；交互语音才使用实时分析。
6. 需要更高准确度或统一多语言效果时，按照 `01-AI模型替换与数据集方案.md` 接入自研 AI 分析器。
